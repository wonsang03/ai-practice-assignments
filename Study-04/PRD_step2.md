# PRD 2단계 — 인식한 재료로 레시피 생성

> 프로젝트: 냉장고를 부탁해 (Study-04) · 상태: **구현 완료** (`recipe.py`, `app.py`의 레시피 추천 화면, `tests/test_recipe.py`)

## 1. 목표

1단계에서 인식한 재료를 사용자가 고친 뒤, 텍스트 생성 모델(GPT `gpt-6-luna`)로 만들 수 있는 요리 레시피를 추천받는다.

## 2. 범위

| 포함 | 제외 |
| --- | --- |
| 인식한 재료 수정·삭제·추가 | 레시피 저장·즐겨찾기 (3단계) |
| 요리 종류·난이도·인원·레시피 개수 선택 | 영양 성분 계산, 장보기 목록 |
| 텍스트 모델로 레시피 1~3개 생성 | 레시피 이미지 생성 |
| 요리명·재료·조리 순서·예상 시간 표시 | 음성 안내 |

## 3. 기능 요구사항

| ID | 요구사항 |
| --- | --- |
| F2-1 | 사이드바에 [재료 인식] / [레시피 생성] 메뉴를 둔다. |
| F2-2 | 1단계 결과(`ingredients`)를 편집 가능한 목록으로 불러온다. 사진 없이 재료를 직접 입력해도 된다. |
| F2-3 | 요리 종류(한식·양식·중식·일식·상관없음), 난이도(쉬움·보통·어려움), 인원(1~4명), 레시피 개수(1~3)를 고른다. |
| F2-4 | "가지고 있는 재료 위주로, 없는 재료는 최소한으로" 쓰도록 지시하고, 추가로 필요한 재료는 따로 표시하게 한다. |
| F2-5 | 레시피마다 요리명, 한 줄 소개, 필요한 재료(보유/추가 구분), 조리 순서(번호), 예상 시간(분), 난이도를 보여 준다. |
| F2-6 | 재료가 하나도 없으면 [레시피 생성] 버튼을 비활성화한다. |
| F2-7 | 생성 결과는 세션에 `recipes`로 보관해 3단계 저장에 쓴다. |

## 4. 화면

```

 요리 종류 ( 한식 ▾ )  난이도 ( 쉬움 ▾ )  인원 ( 2 ▾ )  개수 ( 2 ▾ )

 │ 보유: 계란, 대파 / 추가: 소금                │
 │ 1. … 2. … 3. …                              │
 └─────────────────────────────────────────────┘
```

## 5. API 사양

- 엔드포인트·인증은 1단계와 같다 (`POST {BAZE_BASE_URL}/chat/completions/`, Bearer `BAZE_API_KEY`).
- 모델: `.env`의 `TEXT_MODEL` (기본 `gpt-6-luna`. 처음엔 강의처럼 DeepSeek `deepseek-v4.1-flash`였으나, 더 싸고 현행 모델인 GPT로 바꿈)
- 요청: system 메시지에 역할·출력 형식(JSON만), user 메시지에 재료 목록과 선택 조건.
- 기대 응답:

```json
{"recipes": [{
  "name": "대파 계란말이", "summary": "…",
  "ingredients": {"have": ["계란", "대파"], "need": ["소금"]},
  "steps": ["…", "…"], "minutes": 15, "difficulty": "쉬움"
}]}
```

- 해석은 1단계와 같은 방식(코드 블록 JSON → 본문 JSON)으로 하고, `steps`가 비었거나 `name`이 없는 레시피는 버린다.

## 6. 오류 처리

- 1단계의 상태 코드별 안내(401·402·404·429·5xx·시간 초과·연결 실패)를 그대로 쓴다. 404 안내는 `TEXT_MODEL`을 가리킨다.
- JSON을 해석하지 못하면 "레시피 형식을 이해하지 못했습니다. 다시 생성해 주세요"를 보여 주고 원문은 접어서(expander) 보여 준다.
- 모델이 보유하지 않은 재료를 "보유"로 적으면 "추가"로 옮긴다(입력 재료 목록과 비교).
